# spec: one line, what this delivers

## context
one or two lines. why this exists, what it touches.

## invariants (must hold when done)
- [ ] ...
- [ ] ...
- [ ] everything else behaves as before

each one must be checkable. if you can't name how you'd check it, it isn't an invariant.

## out of scope
what this deliberately does NOT change.

## if one can't be met
what happens when an invariant can't be met: stop, go back to spec or plan, or drop it. never a
patch on top.

## verify
how each invariant is checked - test, command, or manual step. name each one pass or fail.
