# plan-first

before touching code:

1. state the goal in one sentence.
2. list the files you expect to change.
3. name how you'll know it worked (the check).

only then edit. if the change needs more than a few files you didn't expect, stop and re-plan.

## when to abort

stop and hand back if:

- the plan can't name a check for "done".
- the file list keeps growing - the goal isn't understood yet.
- the change wants to touch something the spec never mentioned.

a plan you can't exit cleanly is worse than no plan.
